# SDK lifetime real-render binding

The web runner mounts the real CardPage, YourCardScreen, SumsubKycWrapper, SumsubWebSdkModal, and useSumsubWebSdk with the existing application providers. It intercepts the application network boundary and blocks/records any direct external fetch. It supplies a synthetic `window.snsWebSdk` builder. Each `init` retains the actual refresh function and event handlers registered by the real hook; its launch record derives owner/scope/generation and unique token from the corresponding real resume request and controlled response. The supplied SDK builder's actual `destroy` can be configured to throw. Queued callbacks capture their exact registered function at queue time. `submitted` maps to `onApplicantSubmitted`, `complete` to `onActionSubmitted`, and close uses the real close and Exit controls. The actual modal container is `data-testid=kyc-sumsub-sdk`. The issued-card action is the real “Complete verification” control. Route departure unmounts the real CardPage under its route provider; returning remounts it. The fake does not implement session decisions.

Native is not registered in this harness: the real Cordova bridge routes global `getNewAccessToken` through a module-level active-instance pointer, so it does not expose an invocation-specific old native event as required by the frozen contract. The native SDK also owns a screen outside the DOM. This is unverified native/device coverage, not a pass. A separately representable real native launch boundary can be added without altering frozen web assertions.

The author assertions and public contract were copied byte-for-byte from `/private/tmp/peanut-sdk-lifetime-spec/` and run through a Jest registration shim for the author's Vitest globals. No external provider or network request is permitted.

The first registration attempt found no root-resolvable `@jest/globals` and ran zero tests; the shim was corrected to use Jest globals. The next named positive-control attempt hit the unmodified five-second Jest deadline before an assertion (runner elapsed 72.207 seconds under Node 22 and the supported low-priority wrapper). This is not a behavioral pass or red. Temporary test-only stage output will locate setup/launch delays on the next authorized serial check. Frozen assertions and deadlines remain unchanged.

The subsequent stage-instrumented positive reached the real launch, refresh, and completion callbacks, but the immediate DOM check still saw the SDK container during Headless UI's exit transition. It failed one assertion in 34.295 seconds, and is not evidence of a product callback failure. The harness now flushes four real animation frames during settling: the installed Headless UI transition schedules two frames followed by an additional frame before completing a no-CSS transition. This is an unverified wiring adjustment until the next bounded run.

The four-frame attempt reached mount, initial reads and the real CTA, then hit the unchanged five-second Jest deadline before observing SDK launch; process elapsed 69.25 seconds under the supported low-priority wrapper. The changed-condition attempt did not establish a pass or behavioral red. Temporary stage prints were removed; the external receipt remains `/private/tmp/kyc-sdk-lifetime-frames.log`. A future run needs an evidence-backed improvement in local scheduling or a separately authorized suitable environment; do not repeat unchanged or weaken the deadline.
# Bounded setup scheduling

Every frozen case passes the same A fixture to `mount` (three call sites). The runner creates a fresh actual page and query client in `beforeEach`, under Jest's unchanged hook deadline; the adapter returns that page only for the identical fixture. Each case still drives the real CTA and captured SDK callbacks inside its original unchanged test and deadline, and disposes the page in its existing `finally`. This moves setup only; receipts include the complete mounted-page lifetime.

The fresh query cache is hydrated with the same `/card` eligibility and `/rain/cards` overview DTOs supplied by the network fixture. This removes the initial query wait while preserving the real screen, hooks, continuation decisions and SDK callbacks. Subsequent invalidations use the actual query mechanism and network fixture; all resume and provider-bound observations remain recorded.
